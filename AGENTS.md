# Jobstein development instructions

## Read first
This repository is the durable handover from the prior ChatGPT development session. A new Codex session needs no chat transcript. Read [handover](docs/handover/README.md), [requirements](docs/handover/requirements.md), [status](docs/handover/status.md), [backlog](docs/handover/backlog.md), [local development agent migration](docs/handover/devloop.md), and [architecture](docs/architecture.md). Use actual code, Git history and CI as the source of truth for implementation status.

## Meaning of "keep going"
When asked "keep going", "continue", or "next iteration", carry out the following, not merely a plan:
1. Inspect working tree, branch, remote and recent history. Never overwrite or discard user changes. Work from the latest main revision; fetch first; fast-forward only when safe. If dirty or divergent, preserve work and report the blocker rather than reset/stash without permission.
2. Check GitHub Actions CI for the exact current main SHA. Use gh run list --workflow ci.yml --commit SHA and gh run view RUN_ID; inspect failed logs with gh run view RUN_ID --log-failed. If CI is running, poll every 60 seconds while this foreground session permits. If CI is missing/unavailable, report it and do not claim green. If failed, diagnose and repair before adding features.
3. Select one meaningful bounded item from the backlog, or a necessary prerequisite/real defect. Read relevant code and tests. Do not invent work just to keep committing.
4. Implement, add synthetic tests and document changes and limitations. Run ./gradlew --no-daemon test installDist and bash scripts/smoke-test.sh from repository root. Use other targeted tests as appropriate. Do not commit broken or unverified changes as successful.
5. Review git diff and staged files, ensure no private data, secrets or unrelated edits. Update docs/handover/status.md and backlog when appropriate. Commit only your intended changes. The user has authorized normal commits and non-force pushes to main for this development workflow, subject to existing branch rules. Fetch again before push; if remote moved, stop and reconcile safely; never force-push or bypass protections.
6. Verify GitHub Actions for the exact new SHA. Poll every 60 seconds until terminal when feasible. Report commit, local test and CI results, decisions, blockers and next item. If unable to wait, say CI is pending; the next iteration must gate on it.
7. A plain "keep going" means one complete iteration. A request for ongoing execution may use the separately approved local DevLoop runner; no duplicate agent loops. Stop at scope completion, unavailable integration, required user choice or unsafe operation. Do not expand scope to create artificial milestones.

## Engineering and safety
Use Java 21, Gradle wrapper, Picocli, constructor injection and independently testable services. Keep CLI parsing separate from service orchestration. Prefer explicit optional values over new nullable contracts; maintain compatibility with existing persisted schemas. Prefer fully implemented methods, not placeholders. Never commit real secrets, resumes, tokens or personal data. Use synthetic test fixtures. Fail closed for unavailable integrations and do not report successful provisioning unless verified. Preserve user-wide deduplication and environment isolation. No operational job-search automation in this milestone. Do not send real emails, apply to jobs, access personal Workspace data or create/bill live cloud resources automatically. Live validation requires user-controlled disposable accounts and explicit consent. Do not read unrelated local files. Do not install global software, alter security controls, or enable unattended write access without completing the migration safeguards. The repository is public.

## Handover maintenance
Keep the handover status and backlog concise and current. Never put personal conversation transcripts or real applicant data here. Distinguish implemented, locally tested, CI verified and live verified. Do not hardcode a stale commit as the next baseline; always discover live HEAD. See docs/handover/devloop.md for the separate development-orchestration project. Do not confuse DevLoop with the Jobstein runtime.
